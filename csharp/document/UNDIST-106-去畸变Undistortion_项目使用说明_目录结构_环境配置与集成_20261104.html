1. 一页读懂（30 秒版）

这是什么
把 CPU 去畸变改成 TensorRT 推理：一个原生 DLL（undist_api.dll，C ABI） + 一个 .NET 8 类库（Undistortion.Inference，Mat 进 Mat 出） + 两个可执行程序（最小测试 / 验收工具）。
依赖怎么装（三句话）
① 系统安装：TensorRT 10.14.1.48、CUDA 12.8、VC++ 2015-2022 x64 运行时 → 装到系统 + 配 PATH；
② NuGet：OpenCvSharp4 / OpenCvSharp4.runtime.win 4.13.0.20260627 → PackageReference 自动还原；
③ 我们自己造的：undist_api.dll → 已在 csharp/thirdpart/，拷走即用。
上位机接入三步
① 引用 Undistortion.Inference.dll（或引用项目）； ② 把 thirdpart/undist_api.dll 放到宿主 exe 同目录； ③ 保证 PATH 里有 TensorRT / CUDA 的 bin。 不需要装 VS / CMake / CUDA SDK，不需要编译本项目任何代码。
最小代码
UndistortionConfig（4 字段）→ new Undistorter(config) → Process(src) → Dispose。没有配置文件、没有日志开关、没有缓存开关。
五个命令
build_native.ps1 构建原生 · run_test.ps1 最小验证 · run_verify.ps1 40 图验收 · run_acceptance.ps1 原生四口径 · undist_batch.py 数据集批处理。
为什么强调“三分类”：三类依赖的体积、许可、更新方式完全不同 —— TensorRT 全套 2.8 GB 且受 NVIDIA 许可约束（不能进 git），OpenCvSharp 有 65 MB 原生件（走 NuGet 才不会漏）， 只有 undist_api.dll（88 KB）是我们自己的、必须随源码走。混在一起放一个目录，是部署事故的常见起点。

3. 依赖三分类（核心）

3.1 分类原则

类别判定本项目落点更新方式
① 系统安装 体积大 / 受厂商许可约束 / 与驱动·GPU 强绑定 TensorRT 10.14.1.48、CUDA 12.8、VC++ 2015-2022 x64 系统目录（C:\Program Files\NVIDIA GPU Computing Toolkit\…） 官方安装包 + PATH
② NuGet 有托管包 + 原生件按 RID 分发 OpenCvSharp4 / OpenCvSharp4.runtime.win 全局包缓存 → 输出目录 PackageReference 自动还原
③ thirdpart 我们自己构建、但客户端不应重新构建 undist_api.dll（88 KB） csharp/thirdpart/ build_native.ps1 自动同步（入库）

3.2 ① 系统安装：TensorRT / CUDA / VC++ 运行时

组件版本装完的位置必需文件（举例）
TensorRT10.14.1.48 C:\Program Files\NVIDIA GPU Computing Toolkit\TensorRT\v10.14.1.48\bin nvinfer_10.dll（412 MB）
nvinfer_builder_resource_sm120_10.dll（360 MB，必须，见 5.4）
CUDA12.8 C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8\bin cudart64_12.dll
VC++ 运行时2015-2022 x64System32 MSVCP140.dll / VCRUNTIME140.dll / VCRUNTIME140_1.dll

配 PATH（上位机部署必须做，缺了就是 DllNotFoundException）：

# 临时（当前进程/会话）
$env:PATH = "C:\Program Files\NVIDIA GPU Computing Toolkit\TensorRT\v10.14.1.48\bin;" +
            "C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8\bin;" + $env:PATH

# 永久（机器级，需管理员；部署脚本里做一次即可）
[Environment]::SetEnvironmentVariable('PATH',
  "C:\Program Files\NVIDIA GPU Computing Toolkit\TensorRT\v10.14.1.48\bin;" +
  "C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8\bin;" +
  [Environment]::GetEnvironmentVariable('PATH','Machine'), 'Machine')
为什么这两个不能进 thirdpart：nvinfer_10.dll 单个 412 MB，超过 GitHub 单文件 100 MB 硬限制（push 直接被拒）；TensorRT 的 bin 全套 2.8 GB（各 GPU 架构的 builder resource 加起来）；而且 NVIDIA 的二进制不适合随源码仓库分发。

3.2.1 不需要的库：cuDNN / cuBLAS / plugin / dispatch（实测）

结论
本项目不需要 cuDNN，也不需要 cuBLAS。 nvinfer_plugin_10.dll（50.7 MB）与 nvinfer_dispatch_10.dll（0.6 MB）同样不需要。
为什么
TensorRT 8.0 起 cuDNN 已不是硬依赖：只有用到 Conv/Deconv、RNNv2/LSTM 这类层， 或命中 cuDNN tactic 时，才会在运行期 LoadLibrary 它。 本项目的网络只有 Gather / ElementWise / Cast / Constant / Concatenation / Activation(CLIP) / Unary(FLOOR) —— 没有卷积、没有 RNN、没有 plugin、没有 DLA，所以一次都不会加载 cuDNN。
证据 1：静态依赖
dumpbin /dependents nvinfer_10.dll 只列出 KERNEL32 / USER32 / SHELL32 / ole32 / ADVAPI32 —— 没有 cudnn、没有 cublas （它们是运行期动态加载的，所以静态导入里本来就不该出现）；
undist_api.dll 的直接依赖只有 nvinfer_10 / cudart64_12 / VC 运行时。
证据 2：隔离实测
把程序放进沙箱目录，只放 4 个 DLL：undist_api + nvinfer_10 + nvinfer_builder_resource_sm120_10 + cudart64_12，并把 PATH 收窄成 C:\Windows\system32;C:\Windows （cuDNN 在 CUDA\v12.8\bin，此时既不在沙箱也不在 PATH）。
结果：exit=0，引擎现场构建 + 推理 + 出图全部成功，进程 9.9 s。 （本机其实装了 cuDNN，所以“我这能跑”不能当证据，这个隔离测试才能。）
千万别多拷
cudnn_engines_precompiled64_9.dll 单个 448 MB、cudnn_adv64_9.dll 257 MB、 cudnn_ops64_9.dll 101 MB —— 拷进来纯属白占 1 GB 磁盘，且毫无作用。
什么时候才需要
将来网络里加了卷积/RNN（或换模型、加 cuDNN 系 plugin）才需要 cuDNN 9.x （TRT 10.14 对应 cuDNN 9），届时按第①类：系统安装处理，不要放进 thirdpart。

5. 使用说明

5.1 上位机接入（三步 + 最小代码）

// ① 引用：ProjectReference 或直接引用 Undistortion.Inference.dll
using OpenCvSharp;
using Undistortion.Inference;

// ② 初始化参数 = 一个结构体（没有配置文件）
var config = new UndistortionConfig
{
    MatrixDir = @"D:\opt\undistortion\botong25",   // 12 个 .bin 目录，绝对路径
    Width     = 5120,
    Height    = 4096,
    DeviceId  = 0,
};

// ③ 初始化一次，长期复用
using var undistorter = new Undistorter(config);

// 每帧：Mat 进 → Mat 出
using var dst = undistorter.Process(srcMat);          // 或写入复用缓冲（推荐高频）
undistorter.Process(srcMat, dstMat);
Console.WriteLine(undistorter.LastTiming);            // h2d / infer / d2h / total
配置字段的「必填 / GUI / 校验」写在结构体的 XML 注释里（UndistortionConfig.cs， Visual Studio IntelliSense 直接可见）：MatrixDir 必填 + GUI 必须开放（目录选择）； Width/Height 必填 + GUI 只读展示（随相机/图像带出）； DeviceId 可选（默认 0）+ GUI 必须开放（多卡选卡）。 上位机做配置界面时照这三条生成即可；逐字段细节见 UNDIST-107 §4.2。
成员说明
Undistorter(UndistortionConfig)初始化：表 240 MB + 显存 280 MB，约 8.5 s
Mat Process(Mat src)新建输出 Mat（调用方 Dispose）
void Process(Mat src, Mat dst)写入复用缓冲，避免每帧 20 MB 分配
UndistortionInfo Info尺寸 / 表与显存 / GPU / TRT 版本 / 初始化耗时 / 是否回退 pageable
UndistortionTiming LastTiming最近一次分段耗时
Dispose()幂等；终结器兜底
三条硬约束： ① 只支持单通道 CV_8UC1，尺寸必须等于 Width × Height； ② 单实例单线程（原生一条 stream + 互斥锁），并行请每线程一实例（显存 280 MB/实例）； ③ 初始化只做一次，不要每帧 new。忘记 Dispose 有终结器兜底，但仍建议 using。

5.3 部署形态三选一（实测）

形态体积做法实测结果
A. 环境提供（推荐产线）93.9 MB 拷 dist 目录 + 机器上已装 TRT/CUDA 且 PATH 已配 可用 init 8.5 s / 4.94 ms 每帧
B. 绿色目录866 MB 把 nvinfer_10 / builder_sm120 / cudart 也拷到 exe 同目录，PATH 可有可无；不要带 cuDNN / cuBLAS 实测可用（干净 PATH 下 10.3 ms 首帧）
C. 最小运行≈ 507 MB 预置 .engine 后只带推理运行时（需把缓存能力加回 C# 层） 需要改造 省 360 MB + 启动 1.6 s
两个实测失败案例（部署时最常见）：
① 只拷 dist 但 PATH 没配 → DllNotFoundException: Unable to load DLL 'undist_api' or one of its dependencies (0x8007007E)；
② PATH 配了，但缺 nvinfer_builder_resource_sm120_10.dll → [undist][trt][E] Unable to load library: nvinfer_builder_resource_sm120_10.dll: 126 → C# 侧 UndistortionException: [EngineBuild(-9)]。

5.4 为什么“不缓存引擎”会牵扯到部署

交付层固定不缓存（上位机启动一次、长期运行，6.7 s 一次性成本可接受）。代价是： 客户端必须有“构建引擎”的能力 —— 即 GPU 架构对应的 builder resource（本机 sm_120 = 360 MB）。 如果客户端只想带推理运行时，就必须改成“随包预置 .engine”（形态 C，需要把缓存开关加回结构体，约 1 个字段 + 3 行）。

6. 常见问题速查

现象原因处理
DllNotFoundException … 'undist_api' … 0x8007007E undist_api.dll 不在 exe 目录，或它的依赖（nvinfer_10/cudart64_12）找不到 把 thirdpart/undist_api.dll 放到宿主 exe 同目录；把 TRT/CUDA 的 bin 加进 PATH（或走形态 B）
[EngineBuild(-9)] buildSerializedNetwork 返回空 缺 nvinfer_builder_resource_sm120_10.dll（或架构不匹配），或 TRT 版本不对 安装完整 TensorRT（含 builder resource）；换卡型后确认对应 sm_XX 文件存在
“矩阵 botong25 放哪？能用相对路径吗？” 960 MB 数据，建议放 exe 同级；Test/Tools 默认就找 <exe>\botong25 相对名按 exe 目录解析（不看 CWD）；不要塞进 bin\ 当唯一副本，见 UNDIST-107 §2.1
“要不要一起装/拷 cuDNN？” 不需要。本网络没有 Conv/RNN，cuDNN 一次都不会被加载 见 3.2.1（含隔离实测）；多拷 ≈1 GB 纯浪费
[MatrixMissing(-6)] MatrixDir 不存在或缺 12 个 .bin 检查目录与文件名：U_1..4 / V_1..4 / A1..4
[MatrixSize(-7)] Width/Height 与矩阵实际尺寸不符 让 Width/Height 取待处理图的 Mat.Width/Height（离线工具就是这么做的）
[InvalidImage(-3)] 或 ArgumentException 图非 CV_8UC1、尺寸不符、Mat 非连续、空指针 灰度化 + 尺寸对齐；ROI 先 Clone()
[OutOfMemory(-8)] 显存不足（280 MB/实例）或主机页锁内存不足 减少并发实例；页锁不足会自动回退 pageable（看 Info.PinnedStaging）
启动比预期慢（8~9 s） 现场构建引擎（不缓存） 属正常；要更快就改形态 C（预置 .engine）
多线程调用偶发串行/慢 单实例有原生互斥锁 每线程一个 Undistorter

9. 约定与边界

  • 一个配置概念：UndistortionConfig 结构体（矩阵目录 / 宽 / 高 / 设备号）。 没有 JSON、没有加载器；离线参数走命令行。
  • 日志固定关闭：交付层写死 log_level = 0；需要诊断用 Info / LastTiming / UndistortionException.Code。离线 C++/Python 可自行开日志。
  • 引擎缓存固定关闭：每次现场构建。要改成预置 .engine（形态 C）需加回 1 个字段 + 3 行，见 UNDIST-105 §6.7。
  • 命名约定：命名空间 = 项目名（Undistortion.Inference / Undistortion.Tools）， 一个公开类型一个文件，工具类用 -er。
  • 上传边界：thirdpart/undist_api.dll 入库（交付快照）； TensorRT/CUDA/OpenCvSharp 一律不入库（体积 + 许可）。详见项目根 .gitignore。
