1. 跑之前：三件事就位

类别要准备什么怎么准备
① 系统安装 TensorRT 10.14.1.48、CUDA 12.8、VC++ 2015-2022 x64 运行时 官方安装包 → 把两个 bin 加进 PATH（scripts\_env.ps1 已封装）
② NuGetOpenCvSharp4 4.13.0.20260627 已写在类库 csproj 里，dotnet build 自动还原

2. 配置参数（只有 --image 必填）

Test 是命令行程序，参数只有 4 个，全部来自命令行 —— 没有 JSON、没有环境变量、没有配置文件：

参数必填含义默认值
--image <文件>必填 待去畸变的图像（单通道灰度，如 PIC_1_1.bmp）—
--matrix <目录>可选 去畸变矩阵目录，内含 U_1..U_4 / V_1..V_4 / A1..A4 共 12 个 .bin； 可用相对名（如 botong25），按 exe 所在目录解析 <exe目录>\\botong25
--device <N>可选 CUDA 设备号0
--out <文件>可选 输出 BMP 路径output\<同名>.bmp
为什么没有 --width / --height？ 尺寸本来就由图像决定（矩阵也必须同尺寸）。Test 直接取 src.Width / src.Height 填进结构体， 少两个参数、也就少一种“抄错尺寸”的错。尺寸真的不匹配时，原生会返回 MatrixSize(-7)，不会算错。

另外这些不可配（交付层固定，见 UNDIST-105 §6.6 / §6.7）：

项固定值原因
日志级别0（关）只服务离线调用，上位机不启用
引擎缓存null（每次构建）上位机启动一次、长期运行，6.7 s 一次性成本可接受
通道数 / 搬运模式1 / 库内页锁暂存只支持单通道；页锁不足自动回退

2.1 矩阵放哪（三种做法，按需选一种）

矩阵是 12 个 80 MB 的 .bin，合计 960 MB。它属于“部署数据”，不随 git 走、也不该塞进 bin\ 当唯一副本（bin 被 gitignore，dotnet clean 会连它一起删）。 推荐把 botong25 放在 exe 同级目录，程序默认就找这里：

做法命令 / 操作适用
A. 开发期：目录联接（不复制 960 MB） powershell -File scripts\link_matrix.ps1
在 csharp\Undistortion.Test\bin\Release\net8.0\botong25 建 junction 指向 undistortion_standaloneV0\botong25		 本机联调，改矩阵立刻生效
B. 部署：真实拷贝 把 botong25 整个目录拷到目标 exe 同级 上位机 / 产线装机（安装包负责）
C. 指到别处：--matrix --matrix D:\opt\undistortion\botong25（绝对路径最稳） 矩阵装在公共目录、多程序共用
相对路径的坑（已实测）：如果不做处理，--matrix botong25 会被当成 “当前工作目录”下的 botong25 —— 从资源管理器双击时刚好对，一旦用快捷方式、 计划任务、服务、或别处 cd 后启动，就变成 DirectoryNotFoundException: 矩阵目录不存在: botong25。
所以本程序对 --matrix 的相对路径一律按 exe 所在目录解析（AppContext.BaseDirectory）， 与 CWD 无关；省略时默认也是 <exe>\botong25。
为什么不把矩阵搬进 bin\Release\net8.0 当“源码默认值”？ ① csharp/**/bin/ 被 .gitignore 忽略，960 MB 不会进仓库，别人 clone 下来照样没有； ② dotnet clean / 删 bin 会把数据一起删掉； ③ botong25 还被 undistortion_standaloneV0（CPU 版）和 C++ 验收程序共用， 搬走会让它们找不到。→ 所以她留在原地，由部署/联接派生到 exe 旁。

3. 调用顺序总览

① 读图 Cv2.ImRead(path, Grayscale) // 失败 → src.Empty() → 退出码 3 │ 尺寸 = src.Width × src.Height（后续全部用它） ▼ ② 配置参数 new UndistortionConfig { MatrixDir, Width, Height, DeviceId } │ 栈上值类型，4 个字段，构造后不可改 ▼ ③ 初始化对象 new Undistorter(config) ≈8.5 s（表 1.4 s + 引擎构建 6.7 s） │ 12 个 .bin → 240 MB 表 → 上显存（280 MB）→ 页锁暂存 ▼ ④ 调用 undistorter.Process(src) // 返回新的 Mat（Mat 进 → Mat 出） │ ≈5 ms/帧；undistorter.LastTiming 可读分段耗时 ▼ ⑤ 释放 using 作用域结束 → Dispose() → undist_release 幂等；终结器兜底

4. 四段逻辑逐段看

4.1 加载图像（同时确定尺寸）

// 1) 加载指定图像
using Mat src = Cv2.ImRead(imagePath, ImreadModes.Grayscale);
if (src.Empty())
{
    Console.Error.WriteLine($"读图失败: {imagePath}");
    return 3;
}
要点 1
ImreadModes.Grayscale 强制单通道 —— 库只支持 CV_8UC1。
要点 2
src.Width/Height 就是后面要传给初始化的尺寸，不要另写 5120×4096。
要点 3
using 管住这个 Mat，函数返回时自动 Dispose。

4.2 配置参数：构造结构体

// 2) 初始化参数（结构体就是全部配置）
var config = new UndistortionConfig
{
    MatrixDir = matrixDir,                 // 已解析成绝对路径（默认 <exe>\botong25）
    Width     = src.Width,                 // 尺寸取自图像
    Height    = src.Height,
    DeviceId  = int.TryParse(Arg(args, "--device") ?? "0", out int device) ? device : 0,
};

matrixDir 在构造结构体之前就已经解析好（相对名按 exe 目录）：

// 相对路径按 exe 目录解析（而不是进程的当前工作目录）
static string ResolveFromExeDir(string path) =>
    Path.IsPathRooted(path)
        ? Path.GetFullPath(path)
        : Path.GetFullPath(Path.Combine(AppContext.BaseDirectory, path));

// 默认矩阵位置：exe 同级 botong25
string matrixDir = ResolveFromExeDir(Arg(args, "--matrix") ?? "botong25");
字段类型必填GUI这里怎么来的约束
MatrixDirstring 必填 必须开放
目录选择		 --matrix（默认 <exe>\botong25） 目录必须存在，且含 12 个 .bin
Widthint 必填 只读展示
随相机/图像带出		 src.Width必须与矩阵尺寸一致
Heightint 必填 只读展示 src.Height必须与矩阵尺寸一致
DeviceIdint 可选
默认 0		 必须开放
多卡选卡		 --device≥ 0；越界由原生 InitFailed 兜底
这张表以结构体的 XML 注释为准：UndistortionConfig.cs 里每个字段都写了 「必填 / GUI 处理 / 取值 / 校验」四行说明，Visual Studio 的 IntelliSense 直接可见。 结构体还提供了两个静态数组，可直接用于生成界面：UndistortionConfig.GuiEditableFields（MatrixDir / DeviceId）与
GuiReadOnlyFields（Width / Height）。
上位机做配置界面时按这张表生成即可：MatrixDir 必须可编辑、DeviceId 必须可编辑、 宽高只读展示。

UndistortionConfig 是 readonly struct：只在构造时能赋值，之后不可改 （改尺寸只能重建整个对象）。Validate() 在进原生之前会检查目录是否存在、宽高是否为正，所以 “参数写错”和“引擎起不来”是两种不同的错误。

4.3 初始化对象（最贵的一步）

// 3) 初始化 → 执行 → 4) 离开作用域释放
using var undistorter = new Undistorter(config);
做什么
读 12 个矩阵 → 构建 12 B/px 紧凑表（240 MB）→ 构建 TensorRT 引擎（首次 6.7 s）→ 表与 IO 缓冲上显存（280 MB/实例）→ 分配 2×20 MB 页锁暂存。
要多久
≈8.5 s（表 1.4 s + 引擎 6.7 s，命中缓存才会快，但交付层固定不缓存）。
做几次
一个进程一次。别每帧 new，也别每次请求 new。
失败会怎样
抛 UndistortionException（带原生错误码 + 错误串），或 ArgumentException / DirectoryNotFoundException（配置问题）。
能查什么
undistorter.Info：尺寸、表与显存占用、GPU 名、TRT 版本、初始化耗时、是否回退 pageable。

4.4 调用：Mat 进 → Mat 出

using Mat dst = undistorter.Process(src);
写法行为什么时候用
Mat Process(Mat src)内部新建输出 Mat 并返回（调用方 Dispose） Test 这里；一次性/低频调用
void Process(Mat src, Mat dst)写入你复用的 dst 上位机高频路径：省掉每帧 20 MB 分配
入参硬约束：CV_8UC1（单通道）、尺寸等于 Width × Height、连续内存。 非连续输入（ROI 视图）会内部临时 Clone() 一次；通道或尺寸不符直接 ArgumentException，不会偷偷算错。

4.5 释放：交给 using

// 离开作用域（含异常路径）都会执行：
//   dst.Dispose()        —— 释放输出图
//   undistorter.Dispose() —— 释放句柄：表 + 显存 + 页锁缓冲 + TRT 上下文
//   src.Dispose()        —— 释放输入图
顺序
后进先出：dst → undistorter → src。
幂等
Dispose() 可重复调用；ObjectDisposedException 会在误用时抛出。
忘了会怎样
终结器兜底释放（会晚、但不会漏显存）；仍建议始终 using。
显存口径
每个实例 280 MB；并行就每线程一实例（原生一条 stream + 互斥锁，单实例多线程会串行）。

现象原因改法

8. 从 Test 到上位机：只差一步

Test 里

参数来自命令行：--matrix + 图像尺寸。

var config = new UndistortionConfig
{
    MatrixDir = matrixDir,
    Width = src.Width,
    Height = src.Height,
};

上位机里

参数来自你自己的配置体系（界面 / INI / 数据库），其余完全一样。

var config = new UndistortionConfig
{
    MatrixDir = yourMatrixDir,
    Width = 5120, Height = 4096,
    DeviceId = 0,
};

剩下的就是：引用 Undistortion.Inference.dll、把 undist_api.dll 放到宿主 exe 目录、 把 botong25（960 MB）放到宿主 exe 目录（或给绝对路径）、 机器上装好 TensorRT/CUDA 并配 PATH。初始化一次、长期复用，每帧 Process 即可。 完整依赖与部署形态见 UNDIST-106 项目使用说明。

上位机侧的一条纪律：相对路径按 exe 目录解析，是我们在应用层做的决策（Test / Tools 各自实现）。 类库本身仍把 MatrixDir 原样交给原生库 —— 所以上位机请直接给绝对路径，不要依赖 CWD。
