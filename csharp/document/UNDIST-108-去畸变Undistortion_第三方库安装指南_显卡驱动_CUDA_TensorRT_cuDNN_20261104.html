2. 安装顺序总览

① 显卡驱动 581.57 // 默认路径安装 → 必须重启电脑 │ ▼ cmd: `nvidia-smi` → 看到 Driver Version / 显卡名 ② CUDA Toolkit 12.8 // 默认路径，装时不勾 Display Driver │ → 自动建 CUDA_PATH / CUDA_PATH_V12_8 + PATH ▼ 新开 cmd: `nvcc -V` → release 12.8 ③ cuDNN 9.x（zip） // 解压后把 dll/头/lib 拷进 CUDA 对应目录 │ → bin\*.dll / include\*.h / lib\x64\*.lib ▼ 文件存在性检查（cuDNN 无 CLI） ④ TensorRT 10.14.1.48（zip） // 解压到默认目录 → PATH 加 bin │ ▼ 新开 cmd: `trtexec --version` → [TensorRT v101401] ⑤ 收尾 // 装 VC++ 2015-2022 x64（多数机器已有）→ 跑本项目 run_test.ps1
三条铁律： ① 驱动装完必须重启，否则 nvidia-smi 可能报错或仍显示旧版本；
② 装完 CUDA / TRT 后必须新开一个 cmd / PowerShell —— 已经开着的窗口读不到新的 PATH；
③ 装 CUDA 时不要勾 Display Driver，否则会把刚装好的 581.57 降级成 CUDA 自带的旧驱动。

3.2 安装（默认路径）

驱动步骤的坑：
① 没重启就验证 → 可能仍显示旧驱动版本，或 nvidia-smi 报 “NVIDIA-SMI has failed because it couldn't communicate with the NVIDIA driver”；
② 装成台式机版驱动 → 笔记本会装不上或掉驱动；一定要选 Notebooks 系列；
③ Windows Update 可能后台换成别的驱动版本 → 装完记下版本号，后续排查先对版本；
④ CUDA 安装包里自带驱动，装 CUDA 时若勾了 Display Driver 会降级 → 见 §4 注意事项。

4. 第 2 步CUDA Toolkit 12.8

4.1 下载

developer.nvidia.com/cuda-downloads（或 cuda-12-8-0-download-archive） → Windows → x86_64 → exe (local)，下载完整安装包（约 3~4 GB）。

4.2 安装（默认路径）

  1. 双击 exe，先让它解压到默认临时目录（C:\Users\<你>\AppData\Local\Temp\...），完成后开始安装向导。
  2. 安装位置保持默认：C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8。
  3. 组件勾选：
    • 必装 CUDA Runtime、CUDA Development tools（含 nvcc、头文件、库）
    • 建议 Visual Studio Integration（若机器上装了 VS2022）
    • 取消 Display Driver（驱动已单独装 581.57，避免被降级）
    • 可选 NSight 系列（调试用，不影响运行）
  4. 完成后不需要重启，但要新开一个 cmd / PowerShell 让环境变量生效。

4.3 环境变量（安装器一般已自动建好）

本机实测自动生成了两条系统变量：

变量值作用
CUDA_PATHC:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8 “当前生效的 CUDA 版本”，很多构建脚本靠它定位
CUDA_PATH_V12_8同上多版本共存时按版本号区分

并在 PATH 里追加了三条（顺序如此）：

%CUDA_PATH%\bin
%CUDA_PATH%\libnvvp
%CUDA_PATH%\lib
手动检查/补录方法：Win+R → sysdm.cpl → 高级 → 环境变量 → 在系统变量里改（不是用户变量，否则服务/其他账号看不到）→ 编辑 Path → 新建上述三条。 改完必须新开 cmd。

4.4 验证

# 必须新开一个 cmd！
nvcc -V

本机实测输出：

nvcc: NVIDIA (R) Cuda compiler driver
Copyright (c) 2005-2025 NVIDIA Corporation
Built on Wed_Jan_15_19:38:46_Pacific_Standard_Time_2025
Cuda compilation tools, release 12.8, V12.8.61
Build cuda_12.8.r12.8/compiler.35404655_0
看到什么说明
release 12.8, V12.8.61CUDA Toolkit 装对了（这是 Toolkit 的准，不是驱动的）
where nvcc 输出 …\CUDA\v12.8\bin\nvcc.exe PATH 生效，且解析到期望的那个版本
CUDA 步骤的坑：
① nvcc 不是内部或外部命令 → 90% 是没新开 cmd，其次才是 PATH 没加；
② 装的是 Runtime 而不是 Toolkit → 只有 cudart 没有 nvcc；
③ 机器上有多版本 CUDA → nvcc -V 取 PATH 里第一个，用 where nvcc 确认真实路径； CUDA_PATH 决定构建脚本用哪个；
④ 安装路径带中文或空格 → 部分 CMake/脚本会炸；保持默认路径最稳。

5. 第 3 步cuDNN 9.x（拷进 CUDA 目录）

先说清楚：本项目（Undistortion）不需要 cuDNN。 本项目的 TRT 网络只有 Gather / ElementWise / Cast / Constant / Concat / CLIP / FLOOR， 没有卷积、没有 RNN，cuDNN 一次都不会被加载（已隔离实测，见 UNDIST-106 §3.2.1）。 这一节是为了通用深度学习环境（将来接卷积/RNN 模型、或用其它框架）而写； 只跑本项目可以跳过，但很多 NVIDIA 示例/框架会默认去找 cuDNN。

5.1 下载

developer.nvidia.com/cudnn → 登录后选 Download cuDNN v9.x for CUDA 12.x → Windows x86_64 (zip)。 本机用的是 9.17（包内按 12.9 / 13.1 分目录，属 CUDA 12.x 线，12.8 可用）。

5.2 解压包结构（本机实测）

C:\Program Files\NVIDIA\CUDNN\v9.17\
├── bin\
│   ├── 12.9\        // 8 个 DLL（cudnn64_9.dll、cudnn_adv64_9.dll …）
│   └── 13.1\
├── include\
│   ├── 12.9\        // 7 个头文件（cudnn.h、cudnn_ops.h、cudnn_version.h …）
│   └── 13.1\
├── lib\
│   ├── 12.9\x64\    // 16 个 .lib（带版本号 + 不带版本号的别名）
│   └── 13.1\
├── cudnn_samples\
└── LICENSE
新版 cuDNN（9.1x）为什么有 12.9 / 13.1 子目录？ 一个压缩包里同时带了面向 CUDA 12.x 与 13.x 的二进制。装到 CUDA 12.8 就只用 12.9 这一份（9.x 的 ABI 在 CUDA 12.x 内兼容）。

5.3 拷贝逻辑（常规做法：三处，一个不能少）

把 12.9 目录里的文件分别拷到 CUDA 12.8 的三个对应目录：

从（cuDNN 解压包）到（CUDA 12.8）文件数不拷会怎样
bin\12.9\*.dll C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8\bin\ 8 运行期 DllNotFoundException: cudnn64_9.dll
include\12.9\*.h …\CUDA\v12.8\include\ 7 编译期找不到 cudnn.h，链接失败
lib\12.9\x64\*.lib …\CUDA\v12.8\lib\x64\ 16 编译期 LNK1181: 无法打开输入文件 cudnn.lib

等价命令（管理员 PowerShell；路径按本机实测填好）：

# 源目录（cuDNN 解压位置）
$cudnn = 'C:\Program Files\NVIDIA\CUDNN\v9.17'
$cuda  = 'C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8'

# 1) DLL → CUDA\bin
Copy-Item "$cudnn\bin\12.9\*.dll"  "$cuda\bin\"     -Force
# 2) 头文件 → CUDA\include
Copy-Item "$cudnn\include\12.9\*.h" "$cuda\include\" -Force
# 3) 导入库 → CUDA\lib\x64
Copy-Item "$cudnn\lib\12.9\x64\*.lib" "$cuda\lib\x64\" -Force

5.4 验证（cuDNN 没有 CLI，只能查文件 + 跑一次）

# ① 文件落地检查：应当分别输出 8 / 7 / 16
(Get-ChildItem "$env:CUDA_PATH\bin"     -Filter 'cudnn*.dll').Count
(Get-ChildItem "$env:CUDA_PATH\include" -Filter 'cudnn*.h').Count
(Get-ChildItem "$env:CUDA_PATH\lib\x64" -Filter 'cudnn*.lib').Count

# ② 版本自证：用头文件里的版本宏（3 = 9.17.0）
Select-String "$env:CUDA_PATH\include\cudnn_version.h" -Pattern 'CUDNN_MAJOR|CUDNN_MINOR|CUDNN_PATCHLEVEL'

cudnn_version.h 里能看到 CUDNN_MAJOR 9 等宏，就是 cuDNN 已就位的直接证据。 真正跑通要看具体框架（PyTorch / TensorRT 用到的层），本项目不涉及。

cuDNN 步骤的坑：
① 只拷了 bin → 运行没问题，但自己编译时找不到头/库；三处必须都拷；
② 把 bin\12.9 整个目录拷进 CUDA\bin → 变成 CUDA\bin\12.9\，Loader 找不到；必须拷目录里的文件；
③ 版本线错：给 CUDA 12.x 装 cuDNN for CUDA 13.x → 运行期符号缺失； 认准压缩包里的 12.x 目录；
④ 以为项目需要它 → 本项目不需要（见本节开头的警告），别把 448 MB 的 cudnn_engines_precompiled64_9.dll 当成部署必需项。

6. 第 4 步TensorRT 10.14.1.48

6.1 下载

developer.nvidia.com/tensorrt → Download Now → 登录 → 选 TensorRT 10.14.1 → Windows x86_64 → 与 CUDA 12.x 对应的 zip （文件名形如 TensorRT-10.14.1.48.Windows.x86_64.cuda-12.x.zip，以官网为准）。

6.2 解压到默认目录

TensorRT 是绿色包（解压即用，没有安装程序）。本机解压到：

C:\Program Files\NVIDIA GPU Computing Toolkit\TensorRT\v10.14.1.48\
├── bin\      // nvinfer_10.dll、trtexec.exe、nvinfer_builder_resource_sm120_10.dll …
├── include\  // NvInfer.h 等
├── lib\      // nvinfer_10.lib 等导入库
├── doc\
└── python\   // 可选：Python wheel
必须保留 bin 里的 builder resource 文件。 TensorRT 10.x 把“构建引擎”用的内核资源拆成了按 GPU 架构区分的 DLL （本机 RTX 5060 = sm_120 → nvinfer_builder_resource_sm120_10.dll，约 360 MB）。 删了它，推理能用、构建引擎会失败并报 Unable to load library: nvinfer_builder_resource_sm120_10.dll: 126。 整个 bin 目录约 2.8 GB 属正常，不要“只挑几个 dll”拷到别处。

6.3 环境变量

把 bin 加进系统 PATH（本机实测就这一条）：

%TENSORRT_ROOT%\bin
# 本机实际值（没有 TENSORRT_ROOT 变量时直接写全路径）：
C:\Program Files\NVIDIA GPU Computing Toolkit\TensorRT\v10.14.1.48\bin

注意 DLL 都在 bin 里、lib 里是 .lib 导入库（本机 lib 下 0 个 DLL）， 所以 PATH 只需加 bin；编译期由 CMake 的 link_directories 指向 lib。

6.4 验证

# 新开 cmd
trtexec --version

本机实测输出（首行就是版本证据）：

&&&& RUNNING TensorRT.trtexec [TensorRT v101401] [b48] # …\TensorRT\v10.14.1.48\bin\trtexec.exe --version
[11/04/2026-14:40:46] [I] TF32 is enabled by default. Add --noTF32 flag to further improve accuracy with some performance cost.
=== Model Options ===
  --onnx=<file>               ONNX model
  …（随后打印完整帮助）
看到什么说明
[TensorRT v101401]装对了：v101401 = 10.14.1
后面打印了一大段帮助、退出码为 1 本机实测现象，属正常 该构建在 --version 之后会继续打印帮助并以非 0 退出；只看版本横幅即可。
where trtexec → …\TensorRT\v10.14.1.48\bin\trtexec.exe PATH 生效
TensorRT 步骤的坑：
① trtexec 不是内部或外部命令 → PATH 没加 bin，或没新开 cmd；
② 把 TRT 解压到了带版本号的别处（如 D:\TensorRT）→ 能用，但记得 环境变量/项目脚本里的路径要一起改；本项目默认按 C:\Program Files\NVIDIA GPU Computing Toolkit\TensorRT\v10.14.1.48 找；
③ TRT 版本与 CUDA 不匹配（如 TRT for CUDA 13 装到 CUDA 12 环境）→ nvinfer_10.dll 加载失败或符号缺失；
④ 升级 TRT 后旧的引擎缓存要删（缓存绑定 TRT 版本，头不匹配会自动重建，但会多等几秒）。

9. 常见问题速查（10 条）

#现象原因处理
1'nvidia-smi' 不是内部或外部命令 驱动没装成，或 C:\Windows\System32 被破坏 重装驱动（Notebooks 版）→ 重启；确认 C:\Windows\System32\nvidia-smi.exe 存在
2NVIDIA-SMI has failed because it couldn't communicate with the NVIDIA driver 装完没重启；或驱动被 Windows Update 换掉 重启；再不行重装驱动
3'nvcc' 不是内部或外部命令 没新开 cmd；或 PATH 没加 %CUDA_PATH%\bin；或装的是 Runtime 版 新开 cmd → 仍不行就查 PATH → 仍不行重装 Toolkit
4'trtexec' 不是内部或外部命令 TRT 的 bin 没进 PATH（TRT 是绿色包，不会自动加） 手动加 …\TensorRT\v10.14.1.48\bin 到系统 PATH → 新开 cmd
5nvidia-smi 显示 CUDA Version: 13.0，以为装错了 那是驱动支持的 API 上限，不是 Toolkit 版本 用 nvcc -V 看 Toolkit 真实版本（本机 12.8）
6程序报 cudnn64_9.dll / 符号缺失 cuDNN 没装、只拷了 bin、或版本线与 CUDA 不符 按 §5.3 三处都拷；确认压缩包里用的是 12.x 目录
7链接报 LNK1181: 无法打开输入文件 cudnn.lib 只拷了 DLL，没拷 lib\12.9\x64\*.lib 把 16 个 .lib 拷到 CUDA\v12.8\lib\x64
8构建引擎报 Unable to load library: nvinfer_builder_resource_sm120_10.dll: 126 TRT 的 bin 被裁剪，缺 GPU 架构对应的 builder resource 恢复该文件（或重解压 TRT 包）；不要只挑几个 DLL
9装 CUDA 后驱动版本变回旧版 安装时勾了 Display Driver 重装最新驱动（581.57 或其他 GRD/SD）→ 重启
10C 盘红了 CUDA 5.7 GB + TRT 2.8 GB + cuDNN 解压包 1.3 GB cuDNN 拷完后删解压包（约省 1.3 GB）；TRT 的 doc/、python/ 可不装

10. 与本项目的关系：哪些真必需

组件本项目是否必需说明
显卡驱动必需 CUDA 12.8 要求 R570+ 驱动；本机 581.57 满足
CUDA Toolkit（cudart64_12.dll）必需（运行时） 只有 cudart 是运行期依赖；nvcc 只有自己编译原生库时才需要
TensorRT nvinfer_10.dll必需推理主体，412 MB
TRT nvinfer_builder_resource_sm120_10.dll必需 因为交付层不缓存引擎，每次启动都要现场构建；缺了 → EngineBuild(-9)
VC++ 2015-2022 x64 运行时必需 MSVCP140 / VCRUNTIME140(_1)；多数机器随其它软件已装
cuDNN不需要 网络无 Conv/RNN（隔离实测：不带 cudnn/cublas 也能完整构建+推理）
cuBLAS不需要同上
nvinfer_plugin / nvinfer_dispatch / nvinfer_lean 不需要无自定义 plugin；非 lean 运行时
磁盘占用（本机实测）
CUDA v12.8 5,795 MB · TensorRT 10.14 2,852 MB · cuDNN 解压包 1,304 MB （拷进 CUDA 的只有约 889 MB）→ 全装约 9.7 GB
部署时真正要带的
驱动/CUDA 走安装包；应用目录里只需 undist_api.dll + nvinfer_10.dll + builder resource + cudart64_12.dll（详见 UNDIST-106 §3）
