1. 结论摘要

格式是否相同
完全相同。pageable 与 pinned 都是主机内存里的 H×W 个 uint8， 行优先、无头、无颜色转换；memcpy 可直接互拷。
缓冲建几次
一次创建、循环覆写、最后释放一次。pinned、GPU 显存、输出 Mat 都只建一次； 只有 Cv2.ImRead 每帧返回的解码 Mat 是新建的（OpenCV API 行为）。
释放区别
Mat 用 Dispose/GC；pinned 必须 PinnedBuffer.Dispose （cudaHostUnregister + 句柄释放），不能 free； 库内暂存由 Undistorter.Dispose 释放。
单图耗时
Mat 路径 4.944 ms（其中主机拷贝约 2.215 ms，占 44.8%）； pinned 零拷贝 2.892 ms；pageable 直传 5.904 ms；纯 kernel 1.198 ms。
30 / 100 张（仅算法）
0.148 s / 0.494 s（Mat 路径）；0.087 s / 0.289 s（零拷贝）。
加上启动
+2.225 s（warm）→ 2.373 s / 2.720 s；30 张时启动占 93.8%，100 张占 81.8%。
读 BMP + 算法 + 写 BMP
43.08 ms/张 → 1.293 s / 4.308 s；加启动 3.518 s / 6.534 s。
1000 张（steady）
算法 4.944 s，加启动 7.169 s → 整机等效 139.5 帧/s；相机流水线按 202 帧/s 计。
一句话：算法本身是“百毫秒级”；30/100 张的总时间由启动（2.2 s）和文件 I/O （读+写 38.1 ms/张）主导，GPU 计算只占小头。报指标必须区分“算法节点”与“整帧端到端”。

6. 两条完整调用流程（代码 + 时间线）

6.1 流程 A：pageable Mat 进 → 库内暂存 → GPU → Mat 出

const int W = 5120, H = 4096;
using var und = new Undistorter(matrixDir, W, H,
    new UndistortionOptions { MemoryMode = HostMemoryMode.Pinned }, cache);

// 只建一次：输出 Mat，循环覆写
using var dst = new Mat(H, W, MatType.CV_8UC1);

for (int i = 0; i < 100; i++)
{
    // 每帧解码：新的 pageable Mat（帧结束释放）
    using var frame = Cv2.ImRead(path_i, ImreadModes.Grayscale);

    und.Process(frame, dst);   // 库内：frame→pinIn→GPU→pinOut→dst
    // und.LastTiming.TotalMs ≈ 4.944 ms（含库内两次主机拷贝）
}
t0 frame（pageable） t0→t1 库内 memcpy frame → pinIn ≈ 1.1 ms t1→t2 H2D pinIn → device 0.780 ms t2→t3 kernel 1.172 ms t3→t4 D2H device → pinOut 0.777 ms t4→t5 库内 memcpy pinOut → dst ≈ 1.1 ms t0→t5 total 4.944 ms（LastTiming 包含全部）

6.2 流程 B：pinned 常驻 → 零拷贝 → GPU → pinned 出

const int N = W * H;
using var und = new Undistorter(matrixDir, W, H,
    new UndistortionOptions { MemoryMode = HostMemoryMode.Pinned }, cache);

// 只建一次：页锁输入/输出（POH + cudaHostRegister）
using var pinIn  = new PinnedBuffer(N);
using var pinOut = new PinnedBuffer(N);
using var dst    = new Mat(H, W, MatType.CV_8UC1);  // 仅当下游必须要 Mat

for (int i = 0; i < 100; i++)
{
    using var frame = Cv2.ImRead(path_i, ImreadModes.Grayscale);

    // 上游只能给 pageable Mat：每帧一次拷入（≈1.0 ms，计时外）
    pinIn.CopyFrom(frame.Data, N);

    // 若相机/采集线程直接写 pinIn.Pointer，这一句可完全省略

    und.ProcessPinned(pinIn, pinOut);   // ≈ 2.892 ms

    // 下游直接读 pinOut.Array/Pointer；必须回到 Mat 时再拷回（+≈1.0 ms）
    pinOut.CopyTo(dst.Data, N);
}
pinIn 已持有本帧数据（CopyFrom 不计入 native timing） t1→t2 H2D pinIn → device 0.770 ms t2→t3 kernel 1.354 ms t3→t4 D2H device → pinOut 0.768 ms t1→t4 total 2.892 ms（LastTiming 不含 CopyIn/CopyOut）

9. 分析：启动、I/O 与吞吐

9.1 小批量：启动是绝对大头

30 张 Mat 路径：算法 0.148 s，启动 2.225 s，启动占 93.8%； 100 张：算法 0.494 s，启动占 81.8%。也就是说，30 张时无论换 pinned 还是换 pageable， 总时间都在 2.3–2.4 s 附近，差别只有几十毫秒。

优化顺序应反过来：先把启动从 2.2 s 降下来（离线生成 idx0/fu/fv， 启动只做 H2D，目标 <0.3 s），再谈 kernel 或搬运。

9.2 磁盘批量：解码与 I/O 主导

5120×4096 BMP 的读取+解码约 22.7 ms、写盘约 15.4 ms，合计 38.1 ms/张； 算法只有 4.9 ms，占 11.5%。所以“读 100 张 BMP 再写 100 张”的 4.3 s 里， 真正花在 GPU 上的只有 0.49 s。此时 pinned 相对 staging 的差异（约 0.2 s）会被 I/O 淹没。

9.3 相机/GPU 流水线：算法才是全部

没有文件 I/O 时，1000 帧 Mat 路径 4.944 s（202 帧/s）、零拷贝 2.892 s（346 帧/s）、 kernel 上限 1.198 s（835 帧/s）。此时每一毫秒都直接反映到产能上， 优化搬运（staging → 零拷贝）才有意义。

9.4 尾部延迟：pageable 不可按均值规划

pageable 的 p90 是 8.891 ms，比均值 5.904 ms 高 50.6%；100 张按 p90 估算接近 0.889 s， 而均值只有 0.590 s。实时链路应避免 pageable；必须用普通内存时，按 p90 留余量。

9.5 多实例与扩展

  • 每实例 280 MiB 显存（表 240 + 输入输出 40），8 GiB 卡按显存可开 20+，工程建议 ≤16。
  • 每实例一条 stream，多实例并行会共享 PCIe 与 GPU 计算单元，不会线性加速；
  • 批量摊薄表带宽需要 batch plugin（本版未实现），不是简单开多实例。

10. 常见误区

  1. “pinned 是另一种图像格式”：不是，字节完全一样，只是物理页是否锁定。
  2. “零拷贝 = 不搬图”：不是，PCIe 两程照走；省的是主机侧暂存拷贝。
  3. “pageable 的 5.9 ms 里没有主机拷贝”：有，在驱动内部中转缓冲里，已计入 h2d/d2h。
  4. “staging 用了 pinned，所以接近零拷贝”：不接近，两次主机 memcpy 占 44.8%。
  5. “kernel 1.2 ms 就是端到端”：只有图已经在显存时才成立。
  6. “每帧 new PinnedBuffer 也没事”：注册/分配是毫秒级，必须复用。
  7. “cv.read 100 次 = 100 次算法”：每次 read 还包含 22.7 ms 的解码/IO；算法只占一小部分。
  8. “30 张的总时间 ≈ 30 × 4.9 ms”：只对“进程已启动、内存进内存出”成立；加上启动和 I/O 后完全不同。

11. 结论与建议

结论：pageable / pinned 的格式相同、位置相同（都在主机内存），差别只在物理页是否锁定、 以及每帧是否多两次主机拷贝。算法节点成本：Mat 4.944 ms、零拷贝 2.892 ms、pageable 5.904 ms、 kernel 1.198 ms。30/100 张仅算法为 0.148 / 0.494 s；加启动为 2.373 / 2.720 s； 读 BMP + 写 BMP 为 1.293 / 4.308 s（加启动 3.518 / 6.534 s）。
  1. 缓冲一次创建、循环覆写、最后释放一次；pinned 用 PinnedBuffer， 不要每帧注册；Mat 输出复用，不要每帧新建。
  2. 报指标分两层：算法节点（4.944 / 2.892 ms）与整帧端到端（再加解码、应用拷贝、写盘、启动）。
  3. 小批量先优化启动：2.225 s 在 30 张时占 93.8%；离线表产物可把它压到 <0.3 s。
  4. 磁盘批量先优化 I/O：读+写 38.1 ms/张，是算法的 7.7 倍；能内存进内存出就别落盘。
  5. 实时链路用 pinned 零拷贝：2.892 ms/帧、346 帧/s；前提是采集/下游能直接使用页锁缓冲。
  6. pageable 只做对照：p90 8.891 ms，尾延迟不适合按均值规划产能。

T_mem(N)  = init + N × total_ms
T_disk(N) = init + N × (read + total_ms + write)

init  = 2.225 s（warm）  /  +3.6 s（冷构建引擎）
read  = 22.725 ms/张（BMP imread）
write = 15.415 ms/张（BMP imwrite）
