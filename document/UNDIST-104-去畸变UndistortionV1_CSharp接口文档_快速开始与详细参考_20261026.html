1. 文档说明与两条路径

PART I极简调用

目标：最少代码跑通。一个构造函数 + 一个 Process 调用， 不需要写 YAML、不需要手动建引擎、不需要碰 CUDA。

适合：第一次接入、单图验证、Demo、已有 Mat 管线。

单图 4.94 ms（Mat 进 Mat 出，默认 pinned 暂存）。

PART II详细参考

目标：查参数。构造/属性/方法/返回类型/异常/结构体/错误码/C ABI， 以及生命周期、线程、性能和常见问题。

适合：封装集成、异常处理、C++ 直接调 DLL、性能调优。

零拷贝 2.89 ms（调用方 pinned 缓冲）。

两条路径的共同点：都是「初始化一次 → 每帧推理 → 释放一次」。 区别只在 Part I 用最少的代码，Part II 把所有可调参数与契约摊开。

2. PART I极简调用（初始化 → 直接推理）

2.1 最小可用代码

把下面 5 行逻辑跑通，就完成了去畸变接入：

using OpenCvSharp;
using UndistortionV1Inference;

// 1) 初始化（一次）：矩阵目录 + 目标尺寸
using var und = new Undistorter(@"E:\...\botong25", 5120, 4096);

// 2) 读图 + 推理（每帧）
using var src = Cv2.ImRead(@"E:\...\PIC_1_1.bmp", ImreadModes.Grayscale);
using var dst = new Mat(4096, 5120, MatType.CV_8UC1);
und.Process(src, dst);

// 3) 使用结果
Cv2.ImWrite(@"E:\...\out.bmp", dst);

这就是全部。构造函数内部自动完成：加载 12 个矩阵 → 生成 12 B/px 紧凑表 → 构建/加载 TRT 引擎 → 表上显存 → 分配库内 pinned 暂存。调用方不需要出现 TensorRT、CUDA、engine 文件等概念。

为什么说“最简洁高效启动”：
  • 只有 1 个类、1 个构造、1 个推理方法；
  • 初始化参数只有「矩阵目录 + 宽 + 高」，无需 YAML / engine 路径；
  • 默认走 HostMemoryMode.Pinned，比 pageable 直传快约 1.2×；
  • 输出复用调用方 Mat，不产生每帧 20 MB 的额外分配。

2.3 调用流程与逻辑

① new Undistorter(matrixDir, W, H) │ 加载矩阵/建表/建引擎/表上显存（约 2.2 s，一次） ▼ ② 准备输入：Cv2.ImRead → Mat（CV_8UC1），或 byte[] / PinnedBuffer / 指针 │ ▼ ③ und.Process(src, dst) │ H2D（0.78 ms） → kernel（1.17 ms） → D2H（0.78 ms） │ Mat 路径另含库内两次 memcpy（约 2.2 ms） ▼ ④ 使用 dst：显示、保存、测量、下游算法 │ ▼ ⑤ using / Dispose：释放 engine/表/显存/pinned 暂存（一次）
步骤代码频率典型耗时

读图/解码Cv2.ImRead(...)每帧约 22.7 ms（BMP 5120×4096，含解码）

2.4 最高效路径：pinned 零拷贝

如果追求最低延迟，用 PinnedBuffer 常驻页锁缓冲，调用 ProcessPinned： 

const int N = 5120 * 4096;

// 只建一次：Undistorter + 2 块页锁缓冲
using var und = new Undistorter(matrixDir, 5120, 4096);
using var pinIn  = new PinnedBuffer(N);
using var pinOut = new PinnedBuffer(N);

for (int i = 0; i < 100; i++)
{
    using var frame = Cv2.ImRead(path_i, ImreadModes.Grayscale);

    // 上游只能给 pageable Mat：每帧一次拷入（约 1 ms，计时外）
    pinIn.CopyFrom(frame.Data, N);

    // 若相机/采集线程直接写 pinIn.Pointer，这一句可完全省略

    und.ProcessPinned(pinIn, pinOut);   // ≈ 2.89 ms

    // 下游直接读 pinOut.Array / pinOut.Pointer
}
2.89 ms 的前提：输入/输出缓冲本身是页锁内存且常驻复用。 如果每帧还要从 Mat 拷入、再拷回 Mat，实际约 4.9 ms， 与 Mat 路径基本一样（见 §3-10）。

2.5 三种入口怎么选

入口代码适用单图
Mat（默认）und.Process(srcMat, dstMat) 已有 OpenCV 管线，最省事4.94 ms
PinnedBufferund.ProcessPinned(pinIn, pinOut) 采集/下游能直接使用页锁缓冲2.89 ms
byte[]und.Process(byteArray) 与相机 SDK / 网络包对接，长度 = W×H4.94 ms
裸指针und.Process(srcPtr, stride, dstPtr, stride, pinned) 非托管缓冲、带行跨距取决于 pinned

3.5 方法详解（参数 / 返回 / 异常）

3.5.1 Mat Process(Mat src, Mat? dst = null)

参数类型说明
srcMat 输入图，必须 CV_8UC1、非空、尺寸 = Info.Width/Height；非连续时内部 Clone
dstMat? 可选输出；null 时新建；提供时必须同尺寸/同类型且连续。建议复用，避免每帧 20 MB 分配

返回：输出 Mat（即 dst；dst 为 null 时是新建的）。

异常：ObjectDisposedException、ArgumentNullException（src 为 null）、 ArgumentException（空图 / 非 CV_8UC1 / 尺寸不符 / dst 非法 / dst 不连续）、 UndistortionException（原生推理失败）。

备注：内部走「src → 库内 pinned → GPU → 库内 pinned → dst」， LastTiming.TotalMs 包含两次主机 memcpy（约 4.94 ms）。

3.5.2 byte[] Process(byte[] src)

参数类型说明
srcbyte[] 长度必须 恰好 W×H（20,971,520）；行优先、无 padding

返回：新建的 byte[W×H]。

异常：ObjectDisposedException、ArgumentNullException、 ArgumentException（长度不符）、UndistortionException。

备注：每次调用会 pin 输入/输出数组并走库内暂存；高频路径请改用 PinnedBuffer + ProcessPinned。

3.5.3 void ProcessPinned(PinnedBuffer src, PinnedBuffer dst)

参数类型说明
srcPinnedBuffer 页锁输入，长度 = W×H
dstPinnedBuffer 页锁输出，长度 = W×H

返回：无；结果写入 dst.Array / dst.Pointer。

异常：ObjectDisposedException、ArgumentNullException、 ArgumentException（长度不符）、UndistortionException。

备注：库内不做主机拷贝，LastTiming.TotalMs 约 2.89 ms，但 不含调用方的 CopyFrom/CopyTo。缓冲必须由 PinnedBuffer 创建（已 cudaHostRegister）。

3.5.4 void Process(IntPtr src, int srcStride, IntPtr dst, int dstStride, bool pinnedBuffers = false)

参数类型说明
src / dstIntPtr 非托管缓冲首地址；必须能容纳 W×H 字节
srcStride / dstStrideint 行跨距（字节），必须 ≥ Info.Width；等于宽度时为连续
pinnedBuffersbool true 表示 src/dst 已是页锁内存（host_flags=1）

返回：无；结果写入 dst。

异常：ObjectDisposedException、ArgumentException（指针空 / stride 不足）、 UndistortionException。

备注：该入口不检查尺寸/类型（无法从指针判断），由调用方保证缓冲足够大； 适合相机 SDK、非托管图像、带 padding 的行。

3.5.5 UndistortionTiming BenchKernel(Mat src, int iterations = 50)

参数类型说明
srcMat 必须 CV_8UC1、尺寸 = Info.Width/Height；非连续时内部 Clone
iterationsint 连续 enqueue 次数，≥ 1（默认 50）

返回：UndistortionTiming；其中 InferMs = 平均 kernel 时间， H2dMs = 0、D2hMs = 0、TotalMs = InferMs。

异常：ObjectDisposedException、ArgumentNullException、 ArgumentException（空图/类型/尺寸）、ArgumentOutOfRangeException（iterations < 1）、 UndistortionException。

备注：该调用不更新 LastTiming；用于测“纯 kernel 上限”，不代表端到端。

3.5.6 void SetMemoryMode(HostMemoryMode mode)

参数：Pageable 或 Pinned。

返回：无。异常：ObjectDisposedException、UndistortionException。

备注：只重建/释放库内主机暂存，不重建引擎、不重传表；影响后续 Process(Mat/byte[]/IntPtr) 的 host_flags=0 路径； ProcessPinned 始终零拷贝，不受影响。

3.5.7 UndistortionTiming QueryLastTiming()

返回：最近一次 Process 的计时（与 LastTiming 一致）。

异常：ObjectDisposedException、UndistortionException。

3.5.8 void Dispose()

释放 native 句柄（引擎、表、显存、stream、库内 pinned 暂存）。幂等；未调用时由终结器兜底。 释放后调用任何实例方法抛 ObjectDisposedException。

3.6 PinnedBuffer

public sealed class PinnedBuffer : IDisposable
{
    public PinnedBuffer(int length);
    public byte[] Array { get; }
    public int Length { get; }
    public IntPtr Pointer { get; }
    public void CopyFrom(IntPtr src, int bytes);
    public void CopyTo(IntPtr dst, int bytes);
    public void Dispose();
}
成员说明
PinnedBuffer(int length) 分配 byte[length]（POH）并 cudaHostRegister 注册为页锁内存； length ≤ 0 抛 ArgumentOutOfRangeException，注册失败抛 UndistortionException
Array底层托管数组，可直接读写（长度 = Length）
Length字节数（应 = W×H）
Pointer稳定的页锁首地址，可传给相机/非托管代码
CopyFrom(IntPtr src, int bytes)从任意主机地址 memcpy 到本缓冲；bytes ≤ Length
CopyTo(IntPtr dst, int bytes)从本缓冲 memcpy 到任意主机地址；bytes ≤ Length
Dispose()cudaHostUnregister + 释放 GCHandle；幂等
为什么需要它：托管 GCHandle(Pinned) / POH 只保证“地址不被 GC 移动”， 不是 CUDA 页锁内存；不调用 cudaHostRegister 时，零拷贝会退化为 pageable （实测 5.93 ms vs 2.76 ms）。PinnedBuffer 已封装注册/反注册。

3.9 生命周期、线程与所有权

3.11 FAQ

Q1：为什么构造函数要 2.2 秒？

要读 12 个矩阵（1 GB）并生成 12 B/px 紧凑表；引擎缓存加载约 0.15 s。冷启动构建引擎再加约 3.6 s。 表与引擎都是“一次初始化、常驻显存”，不会每帧重建。

Q2：为什么 Process(Mat) 4.9 ms，ProcessPinned 2.9 ms？

Mat 路径要在库内把 pageable 拷到 pinned、算完再拷回，约 2.2 ms；零拷贝路径省掉这两次 memcpy， 只剩 H2D 0.77 + kernel 1.35 + D2H 0.77。

Q3：一定要用 PinnedBuffer 吗？

不。只有追求 2.9 ms 时才需要。普通 Process(Mat) 开箱即用，4.9 ms。

Q4：GCHandle(Pinned) / POH 能当页锁内存吗？

不能。它只保证 GC 不移动对象，CUDA 仍按 pageable 处理。必须 cudaHostRegister； PinnedBuffer 已封装。

Q5：可以传彩色 Mat 吗？

不可以，只接受 CV_8UC1。彩色请先 Cv2.CvtColor(src, gray, ColorConversionCodes.BGR2GRAY)。

Q6：可以传 ROI / 子矩阵吗？

可以，但必须连续；Process(Mat) 会自动 Clone 非连续输入。 直接 pinIn.CopyFrom(roi.Data, N) 前请确认 roi.IsContinuous()。

Q7：多线程怎么用？

每线程一个 Undistorter。单实例内部串行，不要并发调用。

Q8：报 DllNotFoundException / BadImageFormatException？

前者是 undist_api.dll 不在 exe 目录/PATH；后者是位数不匹配（需 x64）。 还需要 nvinfer_10.dll、cudart64_12.dll。

Q9：引擎缓存能跨机器复制吗？

不能。引擎绑定 GPU 架构与 TensorRT 版本；缓存头会校验 W/H/表结构与 TRT 版本，不匹配会自动重建。

Q10：为什么 Info.MemoryMode 和 MemoryMode 可能不同？

Info 是初始化快照；SetMemoryMode 只更新当前属性 MemoryMode。 以 MemoryMode 为准。

Q11：BenchKernel 会更新 LastTiming 吗？

不会。它返回独立的 timing；LastTiming 只由 Process 系列更新。

Q12：30 / 100 张要多久？

仅算法：0.148 s / 0.494 s（Mat）；0.087 s / 0.289 s（零拷贝）。 加启动：2.373 s / 2.720 s。读 BMP + 写 BMP：1.293 s / 4.308 s（加启动 3.518 s / 6.534 s）。
